# Codex 中的工作流编译、管理和执行规格

第一版规格，已由维护者确认。依据 [已确认的意图](intent.md)。

## 预期行为

### 自然语言入口

用户在当前 Codex 会话中描述要编译、查看、定位、重新编译或执行的工作流。Skill 根据请求识别操作，并使用用户给出的工作流名称、规程内容、文件位置或本次输入。若信息缺失或有多个候选工作流，Skill 指出需要补充或选择的内容，得到足以确定目标的信息后再执行相应操作。

### 编译

- 用户可提供规程正文或可读的规程文件。成功时，Skill 告知工作流名称和编译产物位置，使用户随后可以查看、定位和执行该工作流。
- 规程中存在影响执行的冲突或歧义时，Skill 指出具体规则并请用户澄清。源文件不可读或编译失败时，Skill 说明原因。编译成功后，本次产物才成为可执行结果。

### 管理

- **查看**。用户可以查询已保存的工作流。Skill 返回可供选择的名称，或者明确告知当前没有可用工作流。
- **定位**。用户指定工作流后，Skill 给出其源文和对应的当前编译产物。源文为文件时提供可打开的位置，源文为会话正文时提供可识别的源文记录。找不到指定工作流时，Skill 明确指出找不到的名称。
- **重新编译**。用户可以要求按更新后的规程重新编译既有工作流。成功后，后续定位和执行使用同一工作流名称与新的编译结果。重新编译失败时，Skill 报告失败原因，并告知用户上一份成功产物仍是当前可执行版本。

### 执行

- 用户提供一个可定位的已编译工作流及其本次输入。Skill 按该编译产物规定的角色、分支和结束条件运行，并向用户报告业务结果。
- 工作流需要用户回答时，Skill 把问题带回当前 Codex 会话，收到回答后按流程继续。执行失败时，Skill 报告发生问题的步骤及可获得的原因。

### 条件性斜杠命令

Codex 宿主支持为工作流提供 `/playbook.workflows1` 形式的调用入口时，Skill 提供该入口。以同一工作流和输入调用时，斜杠命令遵循相同的执行规则，并返回相同类型的结果。自然语言入口在两种能力条件下均可独立使用。

## 边界与约束

- 首版宿主为 Codex。工作流编译与执行中涉及 Agent 的步骤，由处理当前请求的 Codex 宿主直接承担，或由它调用原生子 Agent 承担不同角色。Agent 调用沿用当前宿主的身份和权限边界。
- 首版管理操作限于查看、定位和重新编译。
- 斜杠命令的验收以首版目标 Codex 客户端及版本的实际能力为准。验收记录应说明所用客户端、版本和能力判断的依据。

## 验收条件

| 场景 | 通过条件 |
| --- | --- |
| 用自然语言编译新工作流 | 分别用规程正文和规程文件发起编译。两次均可通过普通消息触发，成功后返回工作流名称及产物位置，该名称可在后续请求中引用。 |
| 编译含冲突的规程 | 输入「VIP 退款必须直通」和「超过 500 元必须复核」。Skill 指出 VIP 大额退款的规则冲突并请求澄清。本次编译的结果显示为待澄清，相关草稿保持不可执行。 |
| 查看和定位 | 对照已保存的工作流列表，查询可找到目标名称，并能打开其源文与当前产物或查看对应源文记录。空列表和不存在的名称各自得到明确反馈。 |
| 重新编译 | 修改一条可观察的流程规则，重新编译同名工作流。再次定位时可识别新产物，执行时可观察到新规则。改用含冲突的规程再试时，Skill 报告失败原因或澄清事项。随后用同一名称再次执行，仍能运行上一份成功产物并观察到该产物的规则。 |
| 用自然语言执行已有工作流 | 在另一条普通消息中指定订单核对工作流及 CSV。分别用合规样本和一个触发退回的样本，观察到编译产物规定的角色顺序与两种结束结果，并收到对应业务结果。 |
| 目标或输入不明确 | 给出能指向多个工作流的名称，或省略工作流的必需输入。Skill 请求选择目标或补齐输入，在得到答案前保持等待。 |
| 运行中提问或失败 | 执行一个需要用户决定的分支，确认问题出现在当前 Codex 会话，回答后继续走对应分支。用一个会触发运行失败的输入另跑一次，确认结果指出发生问题的步骤及原因。 |
| 当前宿主承担 Agent 调用 | 分别核对一次涉及 Agent 的编译与一次多角色执行。调用记录能把每次 Agent 调用关联到发起请求的 Codex 会话或由它创建的原生子 Agent。使用原生子 Agent 承担不同角色时，记录能对应角色及其结果。 |
| 斜杠命令条件 | 宿主支持该形式时，对同一工作流及输入分别通过带点号的命令和自然语言执行，核对输入传递、执行规则及结果类型。宿主缺少该能力时，记录依据，并用自然语言完成同一工作流的执行。 |
