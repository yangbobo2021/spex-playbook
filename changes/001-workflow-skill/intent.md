# 在当前宿主 Agent 中编译、管理和执行 Playbook 工作流

第一版意图，已由维护者确认。

## 现有问题

以「订单核对」为例，现有流程需要用 SLC 编译源文、在 Playbook 配置中注册生成的入口并绑定各个角色，最后通过 `playbook run` 提交 CSV 路径。用户要在已经打开的 Agent 会话里复用这类工作流，还得知道产物的位置、运行命令和角色配置。希望把这些操作收进一个 Skill，让用户在当前会话里完成从定义流程到使用流程的工作。

## 受影响的用户

已经在 Codex 中工作，想把一段自然语言规程变成可复用工作流，或想对新输入运行已有工作流的用户。例如，维护订单核对流程的人需要在业务规则修改后重新编译，日常使用者需要用同一流程核对不同的 CSV。

## 期望结果

1. **编译**。用户可以说「把这份订单核对规程编译成工作流」，给出规程内容或位置，并获知编译结果。若规程存在影响执行的歧义，用户能看到需要补充的规则。
2. **管理**。用户可以询问「有哪些工作流」「订单核对用的是哪份规程」，找到已保存的工作流，识别其源文与编译产物，并在规程改变后请求重新编译对应的工作流。
3. **执行**。用户可以说「用订单核对工作流检查这份 CSV」。Skill 根据请求定位已有工作流和本次输入，通过当前宿主运行，并把完成结果、需要回答的问题或失败原因返回给用户。

## 范围与约束

- 首版宿主为 Codex。自然语言是编译、管理和执行的必需入口。用户可以引用工作流名称或规程，执行时可以同时提供本次输入。
- 首版管理操作限于查看、定位和重新编译工作流。
- 工作流涉及的所有 Agent 调用均由当前 Codex 宿主处理。当前宿主可以使用原生子 Agent 承担核对员、修订员和复核员等不同角色。调用使用当前宿主的身份、能力和权限。
- 如果 Codex 支持为工作流提供 `/playbook.workflows1` 形式的调用入口，就实现该入口。自然语言触发始终可用。
